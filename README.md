# Morpho iridescence: angular reflectance datasets

This repository contains two related but distinct datasets and analysis pipelines for angle-resolved reflectance measurements of *Morpho* butterfly wings. Measurements were collected with a goniometer and a spectrometer. The availability of original acquisition files differs between the two datasets; see [Atlas data and reproducibility](atlas/README.md#reproduce-the-processing-steps) before attempting to reproduce the cleaning steps.

| | Gruson protocol ([gruson/](gruson/)) | Morpho Angular Atlas ([atlas/](atlas/)) |
|---|---|---|
| Analysis | Two one-dimensional angular sweeps per specimen, following Gruson et al. (2019) | Two-dimensional angular grids rendered as colour maps |
| Coverage | 20 species; 184 accepted sweeps | 32 specimens; 18,483 cleaned spectra and 2,888 spectra from earlier sweeps of five species |
| Geometry | Constant-span and constant-bisector sweeps | Incidence angle −80° to 80° (10° steps); collection angle −90° to 90° (5° steps) |
| Main outputs | Bmax, t, γB (brightness); Hmax, γH (hue) | Perceived colour, CIE hue, B2, H1, S8 (D65, 2° observer; Montgomerie 2006 / *pavo*) |

The datasets use different acquisition and processing workflows. Do not treat their measurements as interchangeable without consulting the methods documentation.

## Requirements

- Python 3.10 or later for the Python package and scripts.
- R 4.1 or later and the `pavo` R package (version 2.9 or later) for Atlas step 3 only.
- JupyterLab to run the analysis notebooks.

| File | Purpose |
|---|---|
| [requirements.txt](requirements.txt) | Direct dependencies for both pipelines and the notebooks (minimum versions). Start here. |
| [requirements-lock.txt](requirements-lock.txt) | Exact versions of the environment where the Gruson tests passed (Python 3.11.5, Windows). Use it for an exact reproduction. |
| [pyproject.toml](pyproject.toml) | Dependencies of the `morpho_gruson` package (`pip install -e .`). |
| [atlas/scripts/requirements.txt](atlas/scripts/requirements.txt) | Dependencies of the Atlas scripts only. |

The locked environment was validated only with `pytest gruson/tests atlas/tests`. JupyterLab, the notebooks, Atlas steps 1 and 3–7, and the R `pavo` step were not run in it, and R packages have no lock file. See [the release checklist](docs/release_checklist.md) for the remaining reproducibility items.

## Reproduce the Gruson analysis

Run the following from the repository root in a Python environment:

```bash
python -m pip install -r requirements.txt
python -m morpho_gruson.cli run --raw gruson/data/raw --config gruson/config/pipeline.yaml --out gruson/data/processed
python -m pytest gruson/tests
jupyter lab notebooks
```

The regression tests compare the computed species table with the reference tables included in the repository. The notebooks may write figures under `figures/`; inspect and preserve any existing results before rerunning them. See [the Gruson methods](docs/methods.md) and [data dictionary](docs/data_dictionary.md) for definitions, units, and acceptance criteria.

## Reproduce the Atlas

Install [requirements.txt](requirements.txt) (or only [atlas/scripts/requirements.txt](atlas/scripts/requirements.txt) if you do not need the Gruson package), install R with `pavo` ≥ 2.9 for step 3, then follow the staged instructions in [atlas/README.md](atlas/README.md). Atlas processing steps 2–7 can run from the included data products. Step 1, which starts from original acquisition workbooks, cannot be independently reproduced from this distribution because those source workbooks are not included. Do not describe the included angle-corrected spectra as untouched acquisition files.

## Language and source-name policy

Project documentation, code comments, generated column names, and user-facing labels are in English. Original acquisition filenames and headers are retained verbatim where scripts depend on them; examples include Spanish measurement labels and source filenames. Parsing code maps those source labels to English internal values (for example, `brightness` and `hue`). These source strings are compatibility data, not project documentation, and must not be translated or renamed without updating and validating the relevant parser, configuration, tables, tests, and viewer together.
